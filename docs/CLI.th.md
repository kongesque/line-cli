# คู่มือ LINE CLI

[English](CLI.md) | [繁體中文（台灣）](CLI.zh-TW.md) | [日本語](CLI.ja.md) | ภาษาไทย

ใช้บัญชี LINE ส่วนตัวผ่านเทอร์มินัล เพื่ออ่านแชท ส่งข้อความและไฟล์ ดาวน์โหลดไฟล์แนบ
และรับเหตุการณ์ใหม่ ๆ คุณเลือกตามคำแนะนำในเทอร์มินัลได้ หรือใช้ผลลัพธ์ JSON สำหรับสคริปต์

> [!IMPORTANT]
> LINE อนุญาตให้ใช้เซสชันแบบ Chrome ได้ครั้งละหนึ่งเซสชัน การเข้าสู่ระบบด้วย CLI นี้
> อาจแทนที่เซสชันเดิมของส่วนขยาย LINE สำหรับ Chrome หรือไคลเอนต์อื่นที่ใช้เซสชันแบบเดียวกัน

<a id="get-started"></a>

## เริ่มใช้งาน

<a id="install"></a>

### ติดตั้ง

บน macOS หรือ Linux:

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/kongesque/line-cli/main/scripts/install-release.sh | sh
```

ตัวติดตั้งจะเลือกรีลีสที่ตรงกับเครื่อง ตรวจสอบ checksum ติดตั้ง `line` ลงใน `~/.local/bin`
และตั้งค่า `PATH` สำหรับ shell ที่ใช้กันทั่วไป หากมีคำแนะนำให้เปิดเทอร์มินัลใหม่ ให้ทำตาม

บน macOS ใช้ Homebrew ได้ด้วย:

```sh
brew install kongesque/tap/line-cli
```

บน Debian หรือ Ubuntu ให้ติดตั้งเครื่องมือเก็บข้อมูลรับรองก่อนเข้าสู่ระบบ:

```sh
sudo apt install libsecret-tools gnome-keyring
```

keyring ของ Linux ต้องทำงานและปลดล็อกอยู่ใน D-Bus session เดียวกับ `line`
หากใช้ SSH หรือเซิร์ฟเวอร์ที่ไม่มี keyring ที่ปลดล็อกแล้ว ให้ดู
[เซิร์ฟเวอร์ Linux และที่เก็บข้อมูลแบบ headless](#linux-servers-and-headless-storage)

บน Windows ให้เรียกใช้ใน PowerShell:

```powershell
irm https://raw.githubusercontent.com/kongesque/line-cli/main/scripts/install-release.ps1 | iex
```

ตัวติดตั้งจะวาง `line.exe` ใน `%LOCALAPPDATA%\line-cli\bin` และเพิ่มโฟลเดอร์นี้
ลงใน `PATH` ของผู้ใช้ เปิด PowerShell ใหม่หากจำเป็น

ไบนารีของรีลีสยังไม่มีลายเซ็นดิจิทัล ตรวจดูหรือดาวน์โหลดได้จาก
[GitHub Releases](https://github.com/kongesque/line-cli/releases/latest)

ตรวจสอบการติดตั้ง:

```sh
line version
line help
```

<a id="sign-in-and-send-your-first-message"></a>

### เข้าสู่ระบบและส่งข้อความแรก

```sh
line login
line whoami
line chats
line messages "Family group"
line send "Alice" --text "Hello!"
```

`line login` จะแสดง QR code ให้ใช้ LINE บนโทรศัพท์สแกน อนุมัติการเข้าสู่ระบบ
และกรอก PIN ที่แสดงหากระบบขอ รอจนเห็น **Session saved securely** ก่อนใช้คำสั่งอื่น

การเข้าสู่ระบบด้วย QR code ยังเป็นฟีเจอร์ทดลอง หากบัญชี LINE ตั้งค่าอีเมลและรหัสผ่านไว้แล้ว ใช้คำสั่งนี้ได้:

```sh
line login --email you@example.com
```

CLI จะให้กรอกรหัสผ่านโดยไม่แสดงสิ่งที่พิมพ์ และไม่บันทึกรหัสผ่าน
ไม่มีตัวเลือกรหัสผ่านในคำสั่งหรือตัวแปรสภาพแวดล้อมสำหรับรหัสผ่าน

<a id="login-options-and-qr-help"></a>

### ตัวเลือกการเข้าสู่ระบบและการแก้ปัญหา QR code

| คำสั่งหรือตัวเลือก | ใช้เมื่อ |
| --- | --- |
| `line login` หรือ `line login --qr` | ต้องการเข้าสู่ระบบด้วย QR code ในเทอร์มินัล |
| `line login --email ADDRESS` | ต้องการใช้วิธีสำรองด้วยอีเมล รหัสผ่าน และการยืนยันบนโทรศัพท์ |
| `line login --qr-url` | ต้องการค่า QR แบบใช้ครั้งเดียวสำหรับเครื่องมือ QR ในเครื่องที่เชื่อถือได้ |
| `line login --force` | ต้องการข้ามคำถามว่าจะแทนที่เซสชันที่บันทึกไว้หรือไม่ |
| `line login --headless` | ต้องการลงทะเบียนโฮสต์ Linux ที่รองรับ ซึ่งไม่มี keyring ที่ปลดล็อกแล้ว |

ใช้ `--email` ร่วมกับ `--qr` หรือ `--qr-url` ไม่ได้ วิธี QR ทั้งสองแบบต้องมีเทอร์มินัล
ที่รับข้อมูลแบบโต้ตอบได้ แต่เปลี่ยนเส้นทาง stdout ได้ ความคืบหน้า QR code PIN และคำเตือน
จะออกทาง stderr ส่วนข้อความสำเร็จสุดท้ายจะออกทาง stdout

ใช้ตัวสแกนของ LINE อ่าน QR code กรอก PIN ตามที่แสดงทุกหลัก รวมถึงเลขศูนย์ด้านหน้า
การอนุมัติบนโทรศัพท์อย่างเดียวยังไม่ได้หมายความว่า CLI ตรวจสอบโปรไฟล์ ส่งออกคีย์
และบันทึกเซสชันเสร็จแล้ว

ถ้า QR code กว้างเกินเทอร์มินัล CLI จะแจ้งความกว้างที่ต้องใช้และแนะนำ `--qr-url`
โดยไม่แสดงโค้ดที่ถูกตัดขอบ `NO_COLOR` จะปิดการกำหนดสีโดยตรง
ค่าใน `--qr-url` เป็นข้อมูลลับ ใช้กับเครื่องมือในเครื่องที่เชื่อถือได้เท่านั้น
อย่าแชร์ ส่งไปยังเว็บสร้าง QR code หรือบันทึกไว้ ค่านี้ยังคงอยู่ในประวัติการเลื่อนดูของเทอร์มินัล
ระบบไม่บันทึกรูป QR code ก่อนเข้าสู่ระบบด้วย QR ตามปกติ ให้ยกเลิกการตั้งค่า `QRCODE_DEBUG`
เพราะโหมดดีบักของตัวเข้ารหัส QR อาจเขียนข้อมูลออกมา

เวลานับถอยหลังเป็นค่าประมาณ เมื่อ LINE ยืนยันว่า QR code หมดอายุ CLI จะแสดงโค้ดใหม่ได้
สูงสุดสามโค้ดต่อการเข้าสู่ระบบหนึ่งครั้ง ปัญหาเครือข่ายหรือ PIN หมดเวลาจะไม่ทำให้ลองใหม่
เทอร์มินัลแบบพื้นฐานและ stderr ที่เปลี่ยนเส้นทางจะแสดงเฉพาะการเปลี่ยนสถานะ ไม่มีการนับถอยหลังสด

QR login ยังไม่รองรับบัญชีที่ปิด Letter Sealing หากใบรับรอง QR ที่บันทึกไว้ถูกปฏิเสธ
จะไม่เปลี่ยนไปยืนยันด้วย PIN และข้อผิดพลาดใบรับรองที่ไม่รู้จักจะทำให้หยุดเข้าสู่ระบบ
หากพบข้อผิดพลาดในการตรวจสอบใบรับรอง ให้ลองเข้าสู่ระบบด้วยอีเมล
ส่วนท้าย `Diagnostic: verifyCertificate` ถ้ามี จะมีเพียงรหัสตัวเลข
ไม่มี QR, PIN, ใบรับรอง, โทเค็น หรือข้อความตอบกลับจากเซิร์ฟเวอร์

<a id="saved-sessions-and-cancellation"></a>

### เซสชันที่บันทึกไว้และการยกเลิก

ก่อนติดต่อ LINE ระบบจะตรวจสอบที่เก็บข้อมูลในเครื่อง และถามก่อนแทนที่เซสชันที่บันทึกไว้ซึ่งยังใช้งานได้
ตอบ **no** เพื่อเก็บเซสชันเดิม `--force` ข้ามเฉพาะคำถามนี้ ไม่ข้ามการตรวจสอบที่เก็บข้อมูล
การยอมรับที่เก็บข้อมูลแบบ headless การตรวจสอบการใช้เซสชันพร้อมกัน หรือข้อผิดพลาดของโปรโตคอล

Ctrl-C ยกเลิกคำถามและการตรวจสถานะ QR เป็นระยะได้ SIGINT จบด้วยรหัส 130 และ SIGTERM ด้วยรหัส 143
ก่อนจบโปรแกรมจะคืนค่าการแสดงอักขระของเทอร์มินัล คำขอเข้าสู่ระบบด้วยอีเมลแบบเดิม
ยังใช้ค่า HTTP timeout เดิม

หากยกเลิกก่อนบันทึกเซสชันใหม่ เซสชันเดิมในเครื่องจะยังอยู่ แต่ LINE อาจแทนที่เซสชันแบบ Chrome เดิมแล้ว
หากคำขอเข้าสู่ระบบขั้นสุดท้ายไปถึงเซิร์ฟเวอร์ CLI ไม่ส่งคำขอนี้ซ้ำอัตโนมัติ
ถ้ารายงานว่าผลการบันทึกไม่แน่นอน ให้ตรวจสอบด้วย `line auth status --check`
อย่าคืนเซสชันจากสำเนาเก่าหรือเข้าสู่ระบบซ้ำโดยไม่ตรวจสอบ หากได้รับสัญญาณหลังบันทึกสำเร็จแล้ว
ระบบยังจะรายงานว่าบันทึกสำเร็จ

สำหรับ SSH ให้ใช้เทอร์มินัลแบบโต้ตอบ:

```sh
ssh -t user@host
line login
# หรือใช้วิธีสำรองด้วยอีเมล:
line login --email you@example.com
```

การใช้ SSH ไม่ได้ยกเว้นข้อกำหนดเรื่องที่เก็บข้อมูลรับรอง โฮสต์ Linux ที่รองรับ
และไม่มี keyring ที่ปลดล็อกแล้วสามารถใช้[ที่เก็บข้อมูลแบบ headless](#linux-servers-and-headless-storage)ได้

<a id="daily-commands"></a>

## คำสั่งที่ใช้ประจำ

<a id="let-the-cli-guide-you"></a>

### ให้ CLI ช่วยเลือก

ในเทอร์มินัลแบบโต้ตอบ ละรายละเอียดบางอย่างได้:

```sh
line messages
line send
line download
line react
line unsend
```

เลือกห้องแชทหรือข้อความด้วยหมายเลข หรือค้นหาชื่อ ใช้ `n` และ `p` เปลี่ยนหน้า
`q` เพื่อยกเลิก หรือ Ctrl-C เพื่อหยุด `--json` และ `--stdin` จะปิดคำถามแบบโต้ตอบ
สคริปต์จึงต้องระบุอาร์กิวเมนต์ที่จำเป็นให้ครบ

<a id="find-chats-and-people"></a>

### ค้นหาห้องแชทและผู้ใช้

```sh
line chats
line chats --search "Family"
line chats --all --limit 50
line chats --show-ids
line contacts
line contacts --search "Alice"
```

`chats` แสดงห้องแชท ส่วน `contacts` แสดงเพื่อน ในรูปแบบข้อความอ่านทั่วไป ทั้งคู่แสดง 20 รายการโดยค่าเริ่มต้น
JSON แสดงรายการที่ตรงทั้งหมด เว้นแต่กำหนด `--limit` ใช้ `--limit 0` เพื่อแสดงทั้งหมดในรูปแบบข้อความ
`chats --all` จะรวมห้องแชทที่ไม่มีความเคลื่อนไหวด้วย

คำสั่งที่รับ `CHAT` ใช้ ID แบบเต็มของผู้ติดต่อ ห้องแชท หรือกลุ่มได้ หรือใช้ชื่อที่ตรงทั้งหมด
และตรงเพียงรายการเดียว โดยไม่แยกตัวพิมพ์เล็กใหญ่ ชื่อที่มีช่องว่างต้องใส่เครื่องหมายคำพูด
ถ้าไม่พบชื่อหรือมีหลายห้องชื่อซ้ำกัน ให้ใช้ `line chats --search NAME --show-ids` แล้วเลือก ID แบบเต็ม
สคริปต์ควรใช้ ID เพราะชื่ออาจเปลี่ยนได้

หากต้องการค้นหาคนที่ไม่ได้อยู่ในรายชื่อเพื่อน ให้ใช้ MID ของผู้ใช้แบบเต็ม ซึ่งเป็นรหัสระบุตัวผู้ใช้ของ LINE
ตัวอย่างเช่น ฟิลด์ `from` ของข้อความกลุ่มใน `line messages CHAT_ID --json` คือ MID ของผู้ส่ง

```sh
line contacts --mid USER_MID
line contacts --mid FIRST_USER_MID --mid SECOND_USER_MID --json
```

ระบุ `--mid` ซ้ำสำหรับแต่ละคน คำสั่งจะค้นหาเฉพาะ ID ที่ให้มา รักษาลำดับการป้อน
ตัด ID ที่ซ้ำกันทุกตัวอักษรออก และแสดงทุก ID ที่ขอค้นหา โดยไม่เพิ่มใครเป็นเพื่อน
ใช้ MID ของผู้ใช้แบบเต็ม ไม่ใช่ ID กลุ่มหรือห้อง ชื่อที่แสดง หรือ LINE ID สาธารณะ
รองรับรูปแบบเดิม `u` ตามด้วยเลขฐานสิบหกตัวพิมพ์เล็ก 32 ตัว และรูปแบบปัจจุบัน
`u`/`U` ตามด้วยอักขระ base64url 43 ตัว

ผลลัพธ์แบบข้อความจะแสดงแต่ละ MID คู่กับชื่อ โดยใช้ชื่อผู้ติดต่อที่คุณตั้งเองก่อนชื่อในโปรไฟล์
`(unavailable)` หมายถึง LINE ไม่ส่งโปรไฟล์นั้นกลับมา ส่วน `(name unavailable)` หมายถึง
ส่งโปรไฟล์กลับมาแต่ไม่มีชื่อที่ใช้ได้ ทั้งสองกรณีบอกไม่ได้ว่าบัญชีถูกลบแล้วหรือไม่
ใช้ `--search` หรือ `--limit` ร่วมกับ `--mid` ไม่ได้ ดูพฤติกรรมสำหรับสคริปต์ใน
[ผลการค้นหาผู้ใช้แบบ JSON](#json-lookup-results)

<a id="read-messages"></a>

### อ่านข้อความ

```sh
line messages "Alice"
line messages "Alice" --limit 50
line messages "Alice" --show-ids
line messages CHAT_ID --json
```

`messages` ดึงข้อความล่าสุด 1–100 ข้อความ แล้วแสดงจากเก่าไปใหม่
`--show-ids` แสดง ID ที่ต้องใช้สำหรับตอบกลับ แสดงความรู้สึก ดาวน์โหลด และยกเลิกข้อความ

การอ่านประวัติไม่ทำให้ข้อความเป็นอ่านแล้ว และไม่บันทึกเนื้อหาข้อความไว้ในเครื่อง
ข้อความเข้ารหัสเก่าบางข้อความอาจอ่านไม่ได้ หาก LINE ไม่ส่งคีย์ของอุปกรณ์เดิมให้อีกแล้ว

<a id="send-messages-and-files"></a>

### ส่งข้อความและไฟล์

```sh
line send "Alice" --text "Hello!"
line send "Alice" --stdin < message.txt
line send "Alice" --text "Sounds good" --reply-to MESSAGE_ID
line send "Family group" --file ./report.pdf
line send "Family group" --file ./report.pdf --reply-to MESSAGE_ID
```

เลือกเพียงอย่างเดียวระหว่าง `--text`, `--stdin` และ `--file` ข้อความต้องไม่ว่าง
และยาวไม่เกิน 10,000 หน่วย UTF-16 ไฟล์ทั่วไปส่งได้สูงสุด 20 MiB
รูปภาพ วิดีโอ และเสียงที่ส่งด้วย `--file` จะแสดงเป็นไฟล์ทั่วไป

CLI ใช้ Letter Sealing เมื่อห้องแชทรองรับ หากคีย์หาย ข้อมูลสมาชิกกลุ่มไม่ครบ หรือการรับส่งล้มเหลว
ระบบจะหยุดการส่งแบบเข้ารหัส ไม่เปลี่ยนไปส่งข้อความธรรมดาโดยไม่แจ้ง
การส่งเข้ากลุ่มที่ผู้ใช้สั่งโดยตรงเท่านั้นที่ลงทะเบียนคีย์กลุ่มใหม่ได้ และต้องทราบสมาชิกปัจจุบันครบทุกคน

เพิ่ม `--json` เพื่อดู ID ข้อความ สถานะการเข้ารหัส การลงทะเบียนคีย์กลุ่ม และเลขลำดับคำขอ

> [!CAUTION]
> CLI ลองส่งหรือเปลี่ยนแปลงข้อมูลบนเซิร์ฟเวอร์แต่ละครั้งเพียงครั้งเดียว
> หากไม่ได้รับคำตอบ ให้ตรวจสอบใน LINE ก่อนลองใหม่ เพราะการดำเนินการอาจสำเร็จแล้ว

<a id="download-or-change-a-message"></a>

### ดาวน์โหลดไฟล์แนบหรือจัดการข้อความ

หา ID ข้อความด้วย `line messages CHAT --show-ids` หรือ `--json`:

```sh
line download "Alice" --message MESSAGE_ID --output ./received.pdf
line download "Alice" --message IMAGE_MESSAGE_ID --output ./photo.jpg
line react "Alice" --message MESSAGE_ID --reaction love
line react "Alice" --message MESSAGE_ID --remove
line unsend "Alice" --message MY_MESSAGE_ID
```

ตัวเลือกแสดงความรู้สึกคือ `like`, `love`, `laugh`, `surprise`, `sad` และ `angry`
ยกเลิกได้เฉพาะข้อความของคุณเอง โดยขึ้นอยู่กับกฎของเซิร์ฟเวอร์ LINE

คำสั่งเหล่านี้ค้นหาใน 100 ข้อความล่าสุดของห้องที่เลือก การดาวน์โหลดจะไม่เขียนทับไฟล์ที่มีอยู่
และจะตรวจสอบข้อมูลเข้ารหัสก่อนบันทึก ข้อมูลกำกับจากเซิร์ฟเวอร์ไม่สามารถกำหนดพาธปลายทางได้

`download` รองรับข้อความรูปภาพ วิดีโอ เสียง และไฟล์ทั่วไปสูงสุด 20 MiB โดยมีเวลารับส่งไม่เกินสองนาที
ระบบบันทึกข้อมูลสื่อครบทุกไบต์โดยไม่ดัดแปลง การเปลี่ยนนามสกุลไฟล์จึงไม่ได้แปลงรูปแบบ
ไม่รองรับข้อความที่มี `DOWNLOAD_URL` ภายนอก การอ่านและดาวน์โหลดไม่ลงทะเบียนคีย์เข้ารหัสกลุ่ม

หากต้องการส่งข้อมูลไฟล์แนบไปยังคำสั่งอื่น ให้ระบุ ID ห้องและข้อความโดยตรง:

```sh
# ใช้ Bash หรือ shell อื่นที่รองรับ pipefail:
set -o pipefail
line download CHAT_ID --message MESSAGE_ID --output - | consumer
```

แทน `consumer` ด้วยโปรแกรมของคุณ ในโหมดนี้ stdout มีเฉพาะข้อมูลไฟล์แนบ
ส่วนข้อมูลวินิจฉัยออกทาง stderr ไม่มีคำถามแบบโต้ตอบ และใช้ `--json` ไม่ได้
CLI จะไม่เขียนข้อมูลไบนารีลงเทอร์มินัล หากต้องการไฟล์ชื่อ `-` จริง ๆ ให้ใช้ `--output ./-`

ระบบตรวจสอบความถูกต้องของสื่อเข้ารหัสก่อนเขียนไบต์แรก หากดาวน์โหลดหรือตรวจสอบไม่สำเร็จ
จะไม่มีข้อมูลไฟล์แนบออกมา แต่ถ้าท่อส่งข้อมูลขาดหรือยกเลิกหลังเริ่มเขียนแล้ว อาจเหลือข้อมูลไม่ครบ
จึงควรตรวจรหัสจบโปรแกรมและใช้ `pipefail` หากบันทึกเป็นไฟล์ แนะนำ `--output PATH`
เพราะการเปลี่ยนเส้นทางด้วย `>` อาจล้างไฟล์เดิมก่อน CLI เริ่มทำงาน

<a id="watch-new-events"></a>

### รับเหตุการณ์ใหม่

```sh
line watch
line watch --timeout 30s
line watch --limit 10
line watch --from-now
```

`watch` เขียนเหตุการณ์ JSON หนึ่งรายการต่อบรรทัดลง stdout และข้อความสถานะลง stderr
ครั้งแรกเริ่มจาก revision ปัจจุบันของ LINE ครั้งถัดไปเริ่มต่อจากจุดตรวจที่บันทึกไว้
`--from-now` จะทิ้งจุดตรวจนั้นและเริ่มรับเฉพาะเหตุการณ์ใหม่

| เหตุการณ์ | ความหมาย |
| --- | --- |
| `message` | มีการส่งหรือรับข้อความ |
| `operation` | การแจ้งเตือนอื่นจาก LINE |
| `resync_required` | LINE แจ้งว่ามีเหตุการณ์ขาดหาย ให้ดึงห้องแชทและข้อความใหม่ |

ฝั่งรับควรใช้ `revision` ตัดรายการซ้ำ หากโปรแกรมหยุดหลังเขียนเหตุการณ์แต่ก่อนบันทึกจุดตรวจ
เหตุการณ์สุดท้ายอาจปรากฏซ้ำได้ เปิด watcher ได้ครั้งละหนึ่งตัวเท่านั้น

<a id="updating-line-cli"></a>

## อัปเดต LINE CLI

```sh
line update --check
line update
line update --check --json
```

`update` แสดงเวอร์ชันที่ติดตั้ง รีลีสเสถียรล่าสุดบน GitHub วิธีติดตั้ง และไฟล์โปรแกรมที่ตรวจพบ
ใช้งานได้โดยไม่ต้องเข้าสู่ระบบ LINE `--check` ตรวจสอบและแสดงขั้นตอนต่อไปเท่านั้น
ไม่ติดตั้งและไม่ล็อกเซสชัน คำสั่งรับส่งข้อความไม่ตรวจสอบอัปเดต

| วิธีติดตั้ง | การทำงานของ `line update` |
| --- | --- |
| ตัวติดตั้ง standalone ทางการบน macOS/Linux | ดาวน์โหลด ตรวจสอบ และแทนที่ไฟล์โปรแกรมเมื่อมีรีลีสเสถียรใหม่กว่า |
| Homebrew | แสดง `brew upgrade line-cli` โดย Homebrew ยังเป็นผู้จัดการไฟล์โปรแกรม |
| ตัวติดตั้ง standalone ทางการบน Windows | แสดงคำสั่งติดตั้ง PowerShell ให้เรียกใช้หลังคำสั่งนี้จบ |
| บิลด์จากซอร์สโค้ด | แนะนำแท็กรีลีสและขั้นตอนบิลด์จากซอร์ส |
| วิธีติดตั้งที่ไม่รู้จัก | แสดงหน้ารวมรีลีส และแนะนำให้อัปเดตด้วยวิธีติดตั้งเดิม |

การอัปเดตตัวเองต้องมีทั้งบิลด์รีลีสทางการและบันทึกการติดตั้ง `.line-cli-install`
ที่ตัวติดตั้งทางการสร้างไว้ข้างไฟล์โปรแกรม ไบนารีที่คัดลอกเอง การติดตั้งเก่าที่ไม่มีบันทึกนี้
และบิลด์จากซอร์สจะไม่ถูกแทนที่อัตโนมัติ ให้อัปเดตด้วยวิธีเดิม
การเรียกตัวติดตั้งทางการอีกครั้งจะสร้างบันทึกนี้ด้วย รองรับโฟลเดอร์ติดตั้ง standalone ที่กำหนดเอง
คำสั่งอัปเกรด Windows จะตั้ง `LINE_CLI_INSTALL_DIR` เป็นโฟลเดอร์ที่ตรวจพบ เพื่อใช้ตำแหน่งเดิม

ก่อนอัปเดต ให้หยุดคำสั่งและ watcher ที่กำลังทำงาน รวมถึงบริการที่คอยเปิด watcher ใหม่
การแทนที่อัตโนมัติจะถือ lock ของ watcher และเซสชันโดยไม่อ่านข้อมูลรับรอง
หากล็อกอย่างใดอย่างหนึ่งไม่ได้ ระบบจะไม่ทำต่อ อย่าเรียกตัวติดตั้งภายนอกพร้อมกัน

ตัวอัปเดตดาวน์โหลดไฟล์จากแท็กรีลีสที่ตรวจสอบแล้ว ตรวจไฟล์บีบอัดด้วย checksum SHA-256 ของรีลีสนั้น
เตรียมไฟล์โปรแกรมในโฟลเดอร์เดียวกัน แล้วแทนที่ด้วยการเปลี่ยนชื่อแบบอะตอมมิก
หากดาวน์โหลด ตรวจ checksum หรือแตกไฟล์ไม่สำเร็จ ไฟล์โปรแกรมเดิมจะยังอยู่
การดาวน์โหลดและแตกไฟล์มีขีดจำกัดขนาด ไม่ใช้ sudo ไม่ลองติดตั้งซ้ำ ไม่ลดเวอร์ชันที่ใหม่กว่า
และไม่คาดเดาลำดับของบิลด์พัฒนาหรือ prerelease

`--json` เขียนผลลัพธ์หนึ่งรายการลง stdout และข้อมูลวินิจฉัยลง stderr
พฤติกรรมการติดตั้งเหมือนผลลัพธ์แบบข้อความ หากต้องการตรวจสอบอย่างเดียว
ให้ใช้ **ทั้ง `--check` และ `--json`** ฟิลด์มี `current_version`, `latest_version`, `status`,
`installation`, `executable`, `can_self_update`, `release_url` และฟิลด์เสริม
`instructions` กับ `upgrade_command`

สถานะการตรวจสอบคือ `update_available`, `up_to_date`, `ahead` และ `unknown_version`
ติดตั้งสำเร็จจะเป็น `updated` ล้มเหลวเป็น `failed` ส่วน `updated_unconfirmed` หมายถึง
แทนที่ไฟล์แล้วแต่ซิงก์โฟลเดอร์ลงดิสก์ไม่สำเร็จ ให้ตรวจ `line version` ก่อนลองใหม่
`current_version` บันทึกเวอร์ชันที่เริ่มคำสั่งเสมอ หลัง `updated` ค่า `latest_version`
คือเวอร์ชันที่ติดตั้งแล้ว `can_self_update` บอกว่ารองรับการอัปเดตตัวเองหรือไม่ ไม่ได้บอกว่ามีเวอร์ชันใหม่

การตรวจสำเร็จและการแสดงขั้นตอนอัปเดตเองจบด้วยรหัส 0 แม้พบอัปเดต
หากตรวจสอบหรือติดตั้งล้มเหลวจะใช้รหัสที่ไม่ใช่ศูนย์ ถ้าการตรวจครั้งแรกล้มเหลวจะไม่เขียน JSON
แต่ถ้าติดตั้งล้มเหลวจะเขียนผลลัพธ์ก่อนจบด้วยข้อผิดพลาด การยกเลิกใช้รหัสสัญญาณตามปกติ

<a id="use-from-scripts"></a>

## ใช้งานผ่านสคริปต์

<a id="json-output-and-exit-codes"></a>

### ผลลัพธ์ JSON และรหัสจบโปรแกรม

เพิ่ม `--json` ให้คำสั่งที่รองรับ:

```sh
line whoami --json
line contacts --json
line contacts --mid USER_MID --json
line chats --search "Family" --json
line messages CHAT_ID --json
line send CHAT_ID --stdin --json < message.txt
```

JSON ออกทาง stdout ข้อมูลวินิจฉัยออกทาง stderr เมื่อสำเร็จหรือแสดง help จะจบด้วยรหัส 0
ข้อผิดพลาด CLI และเครือข่ายทั่วไปใช้รหัส 1 ข้อผิดพลาดที่เก็บข้อมูลมี
[รหัสเฉพาะ](#storage-exit-codes) SIGINT ใช้ 130 และ SIGTERM ใช้ 143 รายการผลลัพธ์ว่างคือ `[]`

| คำสั่ง | ข้อมูล JSON ที่ใช้บ่อย |
| --- | --- |
| `whoami` | โปรไฟล์และ ID บัญชี |
| `contacts` | ชื่อเพื่อนและ ID |
| `contacts --mid MID` | หนึ่งรายการต่อ MID ที่ขอค้นหาโดยไม่ซ้ำ พร้อมสถานะการค้นหา |
| `chats` | ID ประเภท จำนวนที่ยังไม่อ่าน และเวลาความเคลื่อนไหวถ้ามี |
| `messages` | ID ผู้ส่ง เวลา เนื้อหา การเข้ารหัส และสถานะ |
| `send` | ID ข้อความ ID ห้อง การเข้ารหัส การลงทะเบียนคีย์กลุ่ม และเลขลำดับ |
| `download` | พาธผลลัพธ์ จำนวนไบต์ และ ID ข้อความ |
| `react`, `unsend` | การดำเนินการ ID ห้อง ID ข้อความ และเลขลำดับ |
| `watch` | หนึ่งเหตุการณ์ JSON ต่อบรรทัด |
| `update` | เวอร์ชันที่ติดตั้ง/ล่าสุด สถานะ วิธีติดตั้ง และขั้นตอนต่อไป ใช้ `--check --json` เพื่อตรวจอย่างเดียว |

หากบางข้อความถอดรหัสไม่ได้ `messages --json` ยังเขียนอาร์เรย์ครบพร้อมสถานะของแต่ละข้อความ
แล้วจบด้วยรหัส 1 ไม่แสดงข้อมูลเข้ารหัสเป็นชิ้น ๆ หรือเนื้อหาตอบกลับดิบจากเซิร์ฟเวอร์

<a id="json-lookup-results"></a>

### ผลการค้นหาผู้ใช้แบบ JSON

`contacts --mid MID --json` คืนอาร์เรย์แม้ขอเพียง ID เดียว แต่ละรายการมีฟิลด์เดิม
`mid`, `displayName`, `displayNameOverridden`, `statusMessage`, `picturePath` และฟิลด์เพิ่ม:

| ฟิลด์ | ความหมาย |
| --- | --- |
| `effectiveDisplayName` | ชื่อที่คุณตั้งเอง หรือชื่อโปรไฟล์หากไม่ได้ตั้งเอง เป็นค่าว่างเมื่อไม่มีชื่อ |
| `status` | `resolved` เมื่อ LINE ส่งโปรไฟล์กลับมา หรือ `unavailable` เมื่อไม่ส่ง MID นั้นกลับมา |

หากไม่มีโปรไฟล์ ยังมีรายการที่ระบุ `mid` ตามที่ขอ โดยฟิลด์ชื่อและโปรไฟล์ว่าง
โปรไฟล์ที่ส่งกลับมาก็อาจไม่มีชื่อ ใช้ MID แทนเมื่อแสดงผลได้
จับคู่รายการด้วย `mid` เพราะ ID ที่ป้อนซ้ำจะแสดงเพียงครั้งเดียว

หาก LINE ส่งโปรไฟล์กลับมาครบ คำสั่งจบด้วยรหัส 0 ถ้ามีรายการที่ค้นหาไม่ได้
จะเขียนอาร์เรย์ JSON ครบ รายงานจำนวนทาง stderr และจบด้วยรหัส 1
สคริปต์ยังใช้ JSON นี้เป็นผลลัพธ์บางส่วนได้ หากเกิดข้อผิดพลาดเครือข่าย การยืนยันตัวตน
หรือรูปแบบคำตอบ จะไม่มีอาร์เรย์ผลลัพธ์ แม้ชุดก่อนหน้าจะสำเร็จแล้ว

<a id="account-and-session"></a>

## บัญชีและเซสชัน

<a id="where-your-session-is-stored"></a>

### ที่เก็บเซสชัน

CLI บันทึกบัญชี LINE ได้หนึ่งบัญชีต่อผู้ใช้ระบบปฏิบัติการ

| ระบบ | ที่เก็บข้อมูล |
| --- | --- |
| macOS | Keychain |
| Linux | ไฟล์เซสชันเข้ารหัส โดยเก็บคีย์ใน Secret Service |
| Windows | ไฟล์เซสชันเข้ารหัสด้วย DPAPI ของผู้ใช้ปัจจุบัน |

รหัสผ่านใช้เฉพาะเข้าสู่ระบบและไม่ถูกบันทึก คำสั่งจะล็อกเซสชันระหว่างอัปเดตข้อมูล
หากอีกคำสั่งแจ้งว่าเซสชันกำลังใช้งาน ให้ลองหลังการอัปเดตปัจจุบันเสร็จ

ตรวจสอบที่เก็บข้อมูลในเครื่องโดยไม่ติดต่อ LINE:

```sh
line auth status
line auth status --check --json
```

`auth status` ตรวจว่าที่เก็บข้อมูลในเครื่องเข้าถึงได้หรือไม่ ไม่ติดต่อ LINE ไม่รีเฟรชโทเค็น
และไม่ได้ยืนยันว่าเซสชันที่บันทึกไว้ยังเข้าสู่ระบบได้ หากเข้าถึงไม่ได้จะรายงานว่าอ่านไม่ได้
แทนการบอกว่าออกจากระบบแล้ว `--check` ทดสอบความพร้อมเขียนข้อมูลเท่าที่ทำได้โดยไม่ถามให้ปลดล็อก
macOS Keychain และ Linux Secret Service อาจรายงาน `interactive_check_required`
การตรวจการเขียนแบบเต็มจะทำระหว่างเข้าสู่ระบบแบบโต้ตอบ
สถานะการเข้าถึงแบบ headless หลังรีบูตจะยังเป็น `expected_not_verified` จนกว่าจะทดสอบบนโฮสต์ของคุณ

ลบเซสชันในเครื่อง:

```sh
line logout
```

การออกจากระบบนี้ไม่เพิกถอนเซสชันบนเซิร์ฟเวอร์ LINE

<a id="token-refresh"></a>

### การรีเฟรชโทเค็น

access token ปกติจะถึงจุดที่ต้องรีเฟรชหลังประมาณเจ็ดวัน ซึ่งไม่ได้หมายความว่าเซสชันที่บันทึกไว้
มีอายุคงที่เจ็ดวัน หาก refresh token ที่บันทึกไว้ยังใช้ได้ CLI จะต่ออายุการเข้าถึงอัตโนมัติ
แม้หลังเปิดโปรแกรมใหม่ หากรีเฟรชล้มเหลวต่อเนื่องหรือไม่มี refresh token อาจต้องใช้ `line login`

คำขออ่านอย่างเดียวอาจรีเฟรชข้อมูลรับรองแล้วลองใหม่ได้หนึ่งครั้ง
การส่ง แสดงความรู้สึก ยกเลิกข้อความ และอัปโหลดจะไม่ถูกทำซ้ำอัตโนมัติ
ให้ตรวจใน LINE ก่อนทำซ้ำหากผลไม่แน่นอน watcher จะเชื่อมต่อใหม่ด้วยข้อมูลรับรองที่บันทึกไว้เมื่อจำเป็น

เฉพาะสัญญาณออกจากระบบที่เซิร์ฟเวอร์แจ้งอย่างชัดเจนเท่านั้นที่ทำให้เซสชันถูกระบุว่าใช้ไม่ได้
โทเค็นหมดอายุ HTTP 401/403 ทั่วไป การรีเฟรชถูกปฏิเสธ หรือเครือข่ายล้มเหลวเพียงอย่างเดียว
ไม่ทำให้เซสชันถูกระบุเช่นนั้น สัญญาณออกจากระบบก็ไม่ได้บอกเสมอว่าไคลเอนต์อื่นแทนที่เซสชันหรือไม่
หากเก็บโทเค็นไม่สำเร็จหลังเปลี่ยนโทเค็น ระบบจะหยุดส่งคำขอต่อ เพราะยืนยันไม่ได้ว่าได้บันทึกโทเค็นใหม่แล้ว

ดูช่วงเวลารีเฟรช กฎการลองใหม่ และหลักฐานเส้นทางการเรียกได้ใน
[การตรวจสอบโทเค็นและเซสชัน](../TOKEN_SESSION.md)

<a id="linux-servers-and-headless-storage"></a>

## เซิร์ฟเวอร์ Linux และที่เก็บข้อมูลแบบ headless

<a id="enroll-without-an-unlocked-keyring"></a>

### ลงทะเบียนโดยไม่มี keyring ที่ปลดล็อกแล้ว

บนโฮสต์ Linux ที่รองรับและไม่มี Secret Service keyring ที่ปลดล็อกแล้ว
ให้ลงทะเบียนแบบโต้ตอบโดยใช้ที่เก็บข้อมูลแบบ headless:

```sh
line login --headless --email you@example.com
line auth status
line auth status --check --json
```

ตัวอย่างใช้อีเมล ส่วน `line login --headless` จะเลือก QR login แบบทดลอง
และใช้การป้องกันที่เก็บข้อมูลแบบเดียวกัน การลงทะเบียนยังต้องมีเทอร์มินัลแบบโต้ตอบ
`--headless` ไม่ได้ทำให้เข้าสู่ระบบโดยไม่มีผู้ดูแลได้

ก่อนติดต่อ LINE ระบบจะถามให้ยอมรับการป้องกัน **Host key; no TPM** หรือคีย์ของโฮสต์ที่ไม่มี TPM
`--force` ไม่ข้ามคำถามนี้ ที่เก็บข้อมูลแบบ headless ป้องกันผู้ใช้ทั่วไปคนอื่นได้
แต่ไม่ป้องกัน root มัลแวร์ที่ทำงานด้วยบัญชีคุณ หรือผู้ที่มีสำเนาดิสก์ทั้งลูก
วิธีนี้ไม่มีการป้องกันด้วย TPM หากยกเลิกก่อนบันทึกเซสชันใหม่ จะไม่มีเซสชันใหม่ค้างไว้ในเครื่อง

หลังลงทะเบียน ใช้คำสั่งตามปกติโดยไม่ต้องระบุตัวเลือกที่เก็บข้อมูล
การเข้าสู่ระบบอีกครั้งจะใช้ระบบจัดเก็บที่เลือกไว้ `login --headless` ไม่แปลงหรือเขียนทับเซสชันแบบ native เดิม

ต้องมีตัวช่วย `/usr/bin/systemd-creds` ที่เชื่อถือได้ และตัวกลางจัดการข้อมูลรับรองของผู้ใช้
ใช้บัญชี Unix และโฟลเดอร์ตั้งค่าเดียวกันสำหรับคำสั่งแบบโต้ตอบ SSH cron และบริการ
รองรับ systemd 256–259 โดย Debian 13/systemd 257 และ Ubuntu 26.04/systemd 259
ผ่านการทดสอบใน VM ชั่วคราวแล้ว เวอร์ชันอื่นที่รองรับยังต้องผ่านการตรวจในเครื่อง
เวอร์ชันเก่าและเวอร์ชันใหม่ที่ยังไม่ตรวจสอบจะถูกปฏิเสธ ยังไม่ได้ยืนยันพฤติกรรมบน UniPi หรือ TPM จริง

<a id="move-an-existing-linux-session"></a>

### ย้ายเซสชัน Linux เดิม

ย้ายเซสชันแบบ native ที่ยังเข้าถึงได้ไปยังที่เก็บข้อมูลแบบ headless:

```sh
line auth migrate --storage=headless
```

การย้ายต้องใช้เทอร์มินัลและยอมรับการป้องกันด้วยคีย์โฮสต์อย่างเดียวเช่นเดียวกับการลงทะเบียน
หยุด watcher งานอัตโนมัติ และ CLI เวอร์ชันเก่าก่อน
ระบบรักษาโทเค็น คีย์เข้ารหัส เลขลำดับคำขอ และจุดตรวจของ watch ไว้
โดยไม่ติดต่อ LINE และไม่ถามรหัสผ่าน

หากย้ายแล้วหยุดกลางทาง ให้เรียกคำสั่งเดิมอีกครั้ง อย่าลบ `migration.pending`
หรือแทนที่ `session.enc` เอง `line auth status` จะแจ้ง `migration_pending`
จนกว่าการเก็บกวาดจะสำเร็จ ดูขั้นตอนกู้คืนใน
[การทำงานภายในของที่เก็บข้อมูลแบบ headless](../internal/session/HEADLESS.md)

<a id="run-a-watcher-without-a-login-session"></a>

### เรียก watcher โดยไม่ต้องล็อกอินเข้าระบบปฏิบัติการ

ลงทะเบียนแบบโต้ตอบด้วยบัญชีเฉพาะที่ไม่มีสิทธิ์ผู้ดูแล หลังรีบูตให้เรียก
`line auth status --check` ด้วยผู้ใช้และสภาพแวดล้อมเดียวกับที่บริการจะใช้
รักษา `HOME` และ `XDG_CONFIG_HOME` ให้ตรงกัน คุณต้องติดตั้งและดูแลบริการหรือ cron job เอง
CLI ไม่สร้างให้

สำหรับ systemd user service ให้บันทึกตัวอย่างนี้เป็น
`~/.config/systemd/user/line-watch.service` ของบัญชีที่ลงทะเบียนแล้ว
แก้ `ExecStart` หากไฟล์โปรแกรมอยู่ที่อื่น `%h` หมายถึงโฟลเดอร์ home ของบัญชี
อย่าเพิ่ม `User=` ใน user service

```ini
[Unit]
Description=LINE event watcher
StartLimitIntervalSec=300
StartLimitBurst=5

[Service]
Environment=HOME=%h
Environment=XDG_CONFIG_HOME=%h/.config
UMask=0077
NoNewPrivileges=true
RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6
LockPersonality=true
MemoryDenyWriteExecute=true
ExecStart=/usr/local/bin/line watch
Restart=on-failure
RestartSec=15s
RestartPreventExitStatus=65 69 74 78

[Install]
WantedBy=default.target
```

การตั้งค่านี้ใช้ได้ใน Debian 13/systemd 257.13 ARM64 ตามรายงานใน
[issue #3](https://github.com/kongesque/line-cli/issues/3) ให้ตรวจบนโฮสต์ของคุณก่อนเปิดใช้งาน
`AF_UNIX` ช่วยให้ตัวกลางข้อมูลรับรองทำงาน ส่วน `AF_INET` และ `AF_INET6` อนุญาตการเชื่อมต่อ LINE และ DNS

```sh
systemctl --user daemon-reload
systemctl --user start line-watch.service
systemctl --user status line-watch.service
# เปิดใช้งานเมื่อยืนยันว่าที่เก็บข้อมูลและ watcher ทำงานแล้ว:
systemctl --user enable line-watch.service
```

ผู้ดูแลอาจต้องเปิด lingering เพื่อให้ user service เริ่มได้โดยไม่มีการล็อกอินแบบโต้ตอบ
หากใช้ system service ให้เพิ่ม `User=linebot` ใช้พาธ `/home/linebot` อย่างชัดเจนในตัวแปรสภาพแวดล้อมทั้งสอง
และกำหนด `WantedBy=multi-user.target`

ผลลัพธ์ watch มีข้อความส่วนตัว ให้จำกัดสิทธิ์เข้าถึง journal หรือไฟล์ผลลัพธ์
cron ควรใช้บัญชีและพาธเดียวกัน พร้อม `umask 077`

<a id="diagnose-a-headless-service"></a>

### ตรวจหาปัญหาบริการ headless

การตั้งค่า systemd ต่อไปนี้ทำงานไม่สำเร็จในสภาพแวดล้อม user service ของ
[issue #3](https://github.com/kongesque/line-cli/issues/3):

| การตั้งค่า | ผลที่พบ |
| --- | --- |
| `PrivateTmp=true` | ตัวช่วย headless ใช้งานไม่ได้ จบด้วยรหัส 69 |
| `ProtectSystem=strict` | ตัวช่วย headless ใช้งานไม่ได้ จบด้วยรหัส 69 |
| `ProtectHome=read-only` | จบด้วยรหัสที่ไม่ใช่ศูนย์ รวมถึงเขียนไฟล์ไม่สำเร็จ |

ไม่ต้องใส่ค่าเหล่านี้หรือ `PrivateUsers=` ใน unit พื้นฐาน การเพิ่ม
`ReadWritePaths=%h/.config/line-cli` อย่างเดียวไม่ได้แก้ปัญหาที่รายงาน
นี่เป็นผลจาก user service สภาพแวดล้อมหนึ่ง ไม่ใช่กฎสำหรับ system service ทุกแบบ

user namespace ที่ systemd สร้างอาจซ่อน UID ของ root บนโฮสต์จากบริการของผู้ใช้
เมื่อใช้ `PrivateUsers=true` ตัวช่วยที่ root เป็นเจ้าของอาจแสดงเจ้าของเป็นค่าที่ไม่ได้แมป
([เอกสาร systemd 257](https://github.com/systemd/systemd/blob/v257/man/systemd.exec.xml))
CLI จะปฏิเสธตัวช่วยที่ตรวจสอบเจ้าของและสิทธิ์ไม่ได้ การเมานต์แบบอ่านอย่างเดียวอาจขัดขวาง
การเขียน lock บันทึกพาธ โทเค็นที่รีเฟรช เลขลำดับคำขอ และจุดตรวจของ watch ด้วย
ทั้ง `$XDG_CONFIG_HOME/line-cli` และ `$HOME/.config/line-cli` ต้องเขียนได้ แม้จะเป็นคนละโฟลเดอร์

เรียก `line auth status --check --json` ด้วยผู้ใช้ของบริการ เปรียบเทียบผลในเทอร์มินัลแบบโต้ตอบ
กับใน unit ชั่วคราวที่ใช้สภาพแวดล้อมและการตั้งค่าป้องกันเดียวกัน ตัวอย่างด้านล่างปรับพาธโปรแกรมได้ตามต้องการ:

```sh
systemd-run --user --wait --collect \
  --property=Environment=HOME="$HOME" \
  --property=Environment=XDG_CONFIG_HOME="${XDG_CONFIG_HOME:-$HOME/.config}" \
  --property=UMask=0077 \
  --property=NoNewPrivileges=true \
  --property='RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6' \
  --property=LockPersonality=true \
  --property=MemoryDenyWriteExecute=true \
  /usr/local/bin/line auth status --check --json
```

การตรวจนี้ทำในเครื่องและไม่ติดต่อ LINE เปลี่ยนการตั้งค่า sandbox ทีละอย่าง:

- `headless_helper_untrusted` (รหัส 69) หมายถึงตัวช่วยหรือโฟลเดอร์แม่ไม่ผ่านการตรวจเจ้าของหรือสิทธิ์
  ตรวจการตั้งค่า sandbox ที่ข้อความผิดพลาดระบุ รวมถึงสิทธิ์ของไฟล์ที่ติดตั้งจริง
- `headless_unavailable` หมายถึงค้นหาตัวช่วย ตรวจเวอร์ชัน หรือเรียกใช้ในฐานะ root ไม่สำเร็จ
  ข้อความผิดพลาดจะระบุขั้นตอน
- `storage_unavailable` อาจหมายถึงตัวกลางข้อมูลรับรองหรือการปลดผนึกข้อมูลล้มเหลว
  ระบบไม่แสดง stderr ของตัวช่วย

คืนสภาพแวดล้อมบริการให้ทำงานได้ก่อนพิจารณาลงทะเบียนใหม่หรือลบข้อมูล
หากบริการหยุด ให้แก้ที่เก็บข้อมูล แล้วเรียก `systemctl --user reset-failed line-watch.service`
และเริ่มบริการอีกครั้ง รหัส 69 จะระงับการเปิด watcher ใหม่อัตโนมัติ
นโยบายเปิดใหม่นี้ไม่ใช้กับการส่งหรือการเปลี่ยนแปลงข้อมูลบนเซิร์ฟเวอร์

<a id="linux-session-files-and-upgrades"></a>

### ไฟล์เซสชัน Linux และการอัปเกรด

บน Linux ไฟล์เซสชันเข้ารหัสและ lock ของโปรเซสทั้งสองอยู่ใน `$XDG_CONFIG_HOME/line-cli`
โดยปกติคือ `~/.config/line-cli` การเปลี่ยน `XDG_CACHE_HOME` ไม่เปลี่ยนตำแหน่ง lock
จำกัดสิทธิ์โฟลเดอร์แอปเป็น `0700` และไฟล์เป็น `0600`
CLI ปฏิเสธเจ้าของหรือชนิดไฟล์ที่ไม่ปลอดภัย symlink ที่โฟลเดอร์แอปหรือไฟล์ และไฟล์ที่มี hard link
ระบบไม่เปลี่ยนสิทธิ์โฟลเดอร์แม่ที่มีอยู่แล้วให้อัตโนมัติ

การเข้าสู่ระบบตรวจที่เก็บข้อมูลก่อนถามข้อมูลจากผู้ใช้ แล้วตรวจตัวตนของเซสชันและที่เก็บข้อมูลอีกครั้งก่อนติดต่อ LINE
ใช้รายการข้อมูลรับรองชั่วคราวหรือไฟล์เข้ารหัสแยกต่างหาก โดยเก็บเซสชันปัจจุบันไว้
ถ้าที่เก็บข้อมูลอ่านไม่ได้หรือเสียหาย ให้คืนการเข้าถึงก่อน หรือออกจากระบบอย่างชัดเจนเพื่อลบเซสชันในเครื่อง
หากมีคำสั่งเข้าสู่ระบบหรือออกจากระบบอื่นเปลี่ยนเซสชันระหว่างกรอกข้อมูล ให้เริ่มคำสั่งใหม่

Linux ยังบันทึกพาธเซสชันที่พบใน `native-paths.json` ภายใต้ `$HOME/.config/line-cli`
ถ้ารีลีสเก่าใช้ `XDG_CONFIG_HOME` ตำแหน่งอื่น ให้เรียก `line auth status` หนึ่งครั้งในแต่ละตำแหน่งเดิม
ก่อนย้ายหรือออกจากระบบ เพื่อไม่ให้ลบคีย์ที่โฟลเดอร์อื่นซึ่งระบบรู้จักยังต้องใช้
อย่าลบบันทึกพาธหรือไฟล์ lock เพื่อข้ามขั้นตอน

หยุดคำสั่งและ watcher เก่าก่อนอัปเกรดมาใช้โครงสร้าง lock นี้ ไม่รองรับไบนารีเก่าและใหม่ทำงานพร้อมกัน
เก็บไฟล์ lock ไว้หลังออกจากระบบ การแยกโฟลเดอร์ตั้งค่าไม่ใช่วิธีใช้หลายบัญชีที่รองรับ
เพราะที่เก็บข้อมูล native บน Linux ใช้ตัวระบุคีย์เดียวต่อ Secret Service keyring

หากพบข้อผิดพลาดที่ระบุว่ายืนยันการบันทึกลงดิสก์ไม่ได้ ไฟล์อาจเปลี่ยนไปแล้ว
ให้ทำการดำเนินการในเครื่องแบบเดิมซ้ำ อย่าคืนสำเนาเก่า การออกจากระบบมีบันทึกกู้คืนที่เป็นส่วนตัว
และเรียกซ้ำได้เพื่อเก็บกวาดต่อจากที่หยุดไว้

<a id="storage-exit-codes"></a>

### รหัสจบโปรแกรมสำหรับที่เก็บข้อมูล

| รหัส | ความหมาย |
| --- | --- |
| 65 | รูปแบบไม่ถูกต้อง คีย์หาย การตรวจสอบไม่ผ่าน หรือวิธีป้องกันไม่ตรงกัน |
| 69 | ที่เก็บข้อมูลหรือตัวช่วยใช้ไม่ได้ หรือหมดเวลา |
| 74 | ยืนยันการบันทึกลงดิสก์ไม่ได้ หรือเก็บกวาดข้อมูลทดสอบไม่สำเร็จ |
| 75 | มีการแย่งใช้ทรัพยากรในเครื่อง ที่เก็บข้อมูลเปลี่ยนระหว่างเข้าสู่ระบบ หรือตัวช่วยถูกยกเลิก |
| 78 | ต้องตั้งค่า ยอมรับเงื่อนไข ย้าย ซ่อมแซม หรือตรวจสอบแบบโต้ตอบ |

สัญญาณมีลำดับความสำคัญก่อน: SIGINT ใช้ 130 และ SIGTERM ใช้ 143
ข้อผิดพลาด CLI หรือเครือข่ายอื่นใช้ 1 เมื่อที่เก็บข้อมูลใช้ไม่ได้ `auth status --json`
อาจยังเขียนออบเจ็กต์สถานะ แล้วจบด้วยรหัสที่ไม่ใช่ศูนย์ตามสาเหตุ

## ข้อมูลอ้างอิง

<a id="command-help"></a>

### ดูวิธีใช้คำสั่ง

help ในโปรแกรมมีรายการตัวเลือกปัจจุบัน:

```sh
line help
line login --help
line contacts --help
line chats --help
line messages --help
line send --help
line watch --help
line update --help
```

<a id="build-from-source"></a>

### บิลด์จากซอร์สโค้ด

ต้องมี Git และ Go 1.26 ขึ้นไป บน macOS ต้องมี Xcode Command Line Tools และ CGO เพื่อรองรับ Keychain ด้วย

บน macOS หรือ Linux:

```sh
git clone https://github.com/kongesque/line-cli.git
cd line-cli
./install.sh
```

บน Windows PowerShell:

```powershell
git clone https://github.com/kongesque/line-cli.git
Set-Location line-cli
$env:CGO_ENABLED = "0"
go build -trimpath -o .\bin\line.exe ./cmd/line
.\bin\line.exe help
```

การตรวจสอบสำหรับผู้ร่วมพัฒนา:

```sh
go test -race ./internal/... ./cmd/line ./pkg/line/... ./pkg/e2ee
go vet ./internal/... ./cmd/line ./pkg/line ./pkg/e2ee ./pkg
go build -trimpath -o bin/line ./cmd/line
```

การทดสอบทั่วไปใช้ API และข้อมูลรับรองจำลอง การทดสอบกับ LINE จริงปิดไว้โดยค่าเริ่มต้นและต้องมีการอนุญาตชัดเจน
การทดสอบการยกเลิกใช้โปรเซสลูกจำลอง บน macOS/Linux การทดสอบเทอร์มินัลรหัสผ่านใช้ PTY
จากไลบรารีมาตรฐานของ Python 3 หากมีให้ใช้ การทดสอบร่วมกับ Secret Service จริงบน Linux
ต้องเปิดใช้งาน D-Bus session ชั่วคราวอย่างชัดเจน ส่วนการทดสอบ DPAPI บน Windows ใช้ไฟล์ชั่วคราว

<a id="current-limitations"></a>

### ข้อจำกัดปัจจุบัน

- บันทึกบัญชี LINE ได้หนึ่งบัญชีต่อผู้ใช้ระบบปฏิบัติการ
- QR login ยังเป็นฟีเจอร์ทดลอง และไม่รองรับบัญชีที่ปิด Letter Sealing
- อ่านได้เฉพาะประวัติล่าสุด สูงสุด 100 ข้อความต่อครั้ง
- ส่งไฟล์ทั่วไปได้ แต่ยังไม่รองรับสติกเกอร์หรือการส่งสื่อในรูปแบบเฉพาะ
- ดาวน์โหลดรูปภาพ วิดีโอ เสียง และไฟล์ได้สูงสุด 20 MiB ไม่รองรับ URL สื่อภายนอก
- การอ่านข้อความไม่ทำให้ข้อความเป็นอ่านแล้ว
- ไบนารีของรีลีสยังไม่มีลายเซ็นดิจิทัลและยังไม่ผ่าน notarization
- การเปลี่ยนโปรโตคอลของ LINE อาจกระทบความเข้ากันได้

LINE CLI เป็นโครงการอิสระที่พัฒนาต่อจาก `beeper/line` ไม่ใช่ผลิตภัณฑ์ทางการของ LINE
และไม่ต้องใช้ Beeper หรือ Matrix homeserver
